# 猛虎必勝 — 阪神タイガース ペナントレース勝敗予想

阪神の試合だけを対象にしたサイトです。パ・リーグと優勝予想は扱いません。

畑山・根来・今井の3人による勝敗予想バトルの集計サイト。
オッズは固定値ではなく、直近成績・先発FIP・チームOPS・球場条件から毎日自動で計算されます。

## 構成

```
.
├── index.html                     フロントエンド（UI＋オッズ計算エンジン）
├── data/
│   └── latest.json                自動生成される最新データ（Actionsがコミットする）
├── scripts/
│   ├── update_data.py             NPBデータ収集スクリプト
│   └── requirements.txt
└── .github/workflows/
    └── daily_update.yml           毎日12:00 / 17:00 JST に自動実行
```

CORSの制約を避けるため、フロントは外部サイトを直接叩きません。
**取得はGitHub Actions（サーバー側）で行い、成果物を同一リポジトリの
`data/latest.json` として置く** → サイトはそれを `fetch()` するだけ、という形にしています。

```
GitHub Actions ──(スクレイピング)──> data/latest.json ──(fetch)──> index.html
      ↑ 毎日 12:00 / 17:00 JST                              同一オリジンなのでCORSなし
```

## セットアップ（自動更新を動かすまで）

1. **リポジトリに置いて push**
   このファイル一式（`index.html` / `data/` / `scripts/` / `.github/`）をリポジトリ直下に。
2. **Actionsに書き込み権限を渡す**
   Settings → Actions → General → Workflow permissions を **Read and write permissions** に変更。
   これがないと「データを取ってきたのにcommitできない」で失敗します。
3. **GitHub Pagesを有効化**
   Settings → Pages → Source: `main` / `/ (root)`。
4. **`hanshin_logo.png` を直下に置く**（ヘッダーのロゴ）。
5. **一度手で回して確認**
   Actions タブ → `daily-data-update` → **Run workflow**。
   緑になったら `data/latest.json` が更新され、サイト上部のバーが「最新データ取り込み済み」に変わります。

以降は **毎日 12:00 / 17:00 / 23:00（JST）に自動実行**され、内容に変化があったときだけコミットします。

| 時刻(JST) | 目的 |
|---|---|
| 12:00 | 予告先発・順位表の更新 |
| 17:00 | 試合直前の最終確認（天気・風速もここで） |
| 23:00 | その日の結果・順位・個人成績の反映 |

### 補足

- GitHubのcronは混雑時に**数分〜十数分ずれます**（仕様）。急ぎのときは Run workflow で手動実行してください。
- スケジュール実行は「60日間リポジトリに動きがないと自動停止」しますが、このワークフロー自身が毎日コミットするので止まりません。
- ページを開いたままでも**5分ごとに自動で読み直し**ます。他のアプリから戻ってきたときにも取り直すので、スマホで開きっぱなしでも最新です。すぐ更新したいときは上部バーの「再取得」を押してください。

## ローカルでの確認

```bash
pip install -r scripts/requirements.txt
python scripts/update_data.py --dry-run          # 取得結果を標準出力で確認
python scripts/update_data.py --date 2026-08-21  # 日付を指定
python -m http.server 8000                       # file:// だとfetchが動かないので必ずサーバー経由で
```

## データの流れ

| 項目 | 取得元 | 使いみち |
|---|---|---|
| セ・リーグ順位表、直近10試合、連勝連敗 | NPB公式 + スポナビ日程 | 順位表セクション、オッズの勝率差 |
| チーム打率・OPS・防御率 | NPB公式（チーム成績） | オッズのOPS差、球団一覧 |
| 個人成績（野手・投手） | NPB公式（球団別個人成績） | 選手成績セクション、FIP辞書 |
| 予告先発・球場 | スポナビ日程 | 今日の試合カード、先発FIP |
| 天気・風速 | Open-Meteo | 浜風の補正値 |

FIPは要件どおりの簡易式で計算しています。

```
FIP = (13×被本塁打 + 3×(与四球 + 与死球) − 2×奪三振) ÷ 投球回 + 3.20
```

浜風は、風向を球場の軸（甲子園は南西＝225°を既定）に射影した成分だけを取り出します。
実測とずれる場合は `scripts/update_data.py` の `PARKS["甲子園"]["hamakaze_from"]` を調整してください。

## オッズの計算式

`index.html` の `calculateOdds(hanshinData, opponentData, conditions)`。

```
z = シーズン勝率差×2.00 + 直近10勝率差×0.35 + FIP差×0.42 + OPS差×2.50 + 会場補正 + 浜風
p = 1 / (1 + e^-z)          ※ 30%〜70%にクリップ（1試合単位では一方的にならないため）
阪神のオッズ = (1 / p) × (1 − 控除率0.10)
相手のオッズ = (1 / (1−p)) × (1 − 控除率0.10)
```

係数は `ODDS_MODEL` にまとめてあります。シーズンの実測が溜まったら再校正してください。

## 注意

- スクレイピング先のHTML構造が変わると取得できなくなることがあります。
  その場合もセクション単位で前回値を引き継ぐので、サイトが空になることはありません。
  Actions のログ（`update-log-*` アーティファクト）に失敗したセクションが出ます。
- 相手サーバーに負荷をかけないよう、リクエスト間隔を空けています。
- 予告先発は発表前だと取れません。その場合は前回のローテーションのまま表示されます。
